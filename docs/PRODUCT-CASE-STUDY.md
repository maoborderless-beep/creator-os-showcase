# 产品案例｜让灵感走向行动

Creator OS 面向管理多个内容渠道的个人创作者。创作素材容易散落在链接、待办和日历之间；项目围绕“收藏—安排—执行—复盘”整理工作流。已有 Creator Cockpit 提供内容流程、目标和复盘等基础，我在此之上负责产品规划、交互设计方向、AI 辅助开发的任务拆分与审查、质量验收和迭代决策。实现由人和 AI 辅助协作完成，不是从零独立手写。

## 决策一：重复时提醒，由创作者决定

**问题：**同一素材可能以不同链接分享，而视频分段、播放列表或页面锚点又可能指向不同上下文。错误合并会丢掉备注和整理信息。

**方案：**收藏前只读检查已有素材，按可信内容身份或保守规范化 URL 区分“已收藏”“可能相关”和无法判断；提醒中允许查看原卡、取消或继续收藏。

**取舍：**不自动合并，也不猜测未知短链落点。未出现提醒不保证没有重复，最终检查与写入间仍有短暂竞态，不能称为全局唯一约束。

**实施与验证：**P1.3-B 对旧卡字段保持不变；331 项阶段回归通过，并在独立 Chrome 与 WKWebView 合成工作区验证取消、继续收藏、混合批次和失败重试等场景。测试不是平台全量抓取能力证明。

## 决策二：独立的通用任务模型

**问题：**创作者既有内容制作步骤，也有不对应某条内容的筹备和复盘任务。把所有任务强制绑定内容，会产生多余记录并限制安排。

**方案：**增加独立任务，包含状态、类别、优先级及可选截止时间；接入今日待办、任务列表与日历，同时保留已有内容阶段。

**取舍：**任务不会自动创建内容、客户、合同或收入。无日期任务留在列表；任务与内容阶段分别管理，用户需要主动建立自己的工作习惯。

**实施与验证：**任务事务读取最新工作区，只修改任务并检查版本冲突；旧模块保存保留最新任务。P2-B 记录 443 项回归通过，合成环境分别验证浏览器和 WKWebView 的交互及并发保护。没有将这视为真实用户效率提升。

## 决策三：本地优先与隔离验收

**问题：**创作者的历史素材与排期积累在工作区，读取故障、更新或恢复操作不应静默覆盖数据；测试也不应污染日常数据。

**方案：**桌面端使用独立 WKWebView IndexedDB；读取失败时进入保护状态，导入前预览并由用户选择合并或覆盖。测试使用独立浏览器配置、WebKit Store 和虚构数据；正式更新另行备份与验证。

**取舍：**本地优先不等于自动云同步或所有功能均离线。用户需要主动导出并保管备份；隔离测试和内存兼容检查不等同于真实工作区的覆盖恢复演练。

**实施与验证：**阶段记录包含合成环境导入、恢复及退出重开检查，也记录过正式原生菜单问题和回滚。测试数量与阶段详见 [迭代记录](ITERATION-HISTORY.md)；外部 Beta、跨账户新机安装和真实用户成效均未完成验证。
